# 班级管理

## 可用流程

教师：`My Classes` → 创建班级 → 生成邀请码或导入已有学生 → 分配课程 → 查看成员和课程安排。

学生：`My Classes` → 输入教师提供的邀请码 → 进入班级 → 查看截止日期 → 点击 Start learning 学习指定版本。

- 教师可修改班级名称/说明、查看成员名单、移除成员、撤销课程分配。
- 邀请码有效期 7 天；重新生成立即替换旧码，不影响现有成员。数据库只保存 SHA-256 哈希；学生账号每 15 分钟最多尝试 10 次，失败请求也计数。邀请码只在生成时返回，刷新页面后需重新生成。
- 教师可批量导入已注册学生邮箱（逗号/换行分隔）；重复成员不重复加入，未知邮箱和非学生账号返回未匹配项，不创建账号或默认密码。
- 不发送邮件；`inviteStudents / acceptInvitation` 仍为 reserved。若移除成员后不希望其凭旧码重新加入，应先更换邀请码；移除不是永久封禁。
- 只能分配自己已发布、未下架的教学课程及其既有发布版本；个人课程不可分配。班级分配不把公开课程变成私有课程。
- 截止日期是学习提醒，截止后不自动锁课（日期按香港时间 UTC+8 记至当日结束）。相同班级/课程/版本分配幂等，保持原截止日期；撤销后重新分配可填写新的截止日期。
- 暂不提供删除班级、邮件邀请、班级转让或全班成绩报表。已有 Teaching Management 的反馈功能保留。

## 学生端与版本规则

原有课程目录、自建课程、学习路径和独立选课继续使用。新增班级列表、加入弹窗和班级课程页面；不将班级安排自动写进 AI 学习路径。

分配链接为 `/student/courses/<id>?version=<发布版本>`。页面读取这个版本的不可变快照，练习提交同时携带版本；服务和 SQL 在写入前再次检查版本、活动归属、当前角色和访问来源。发布新版本不会改变旧班级安排或把旧回答算到新版本。

`enrollments.direct_access` 区分真正独立选课与仅为历史外键保留的记录：

1. 现有加入记录迁移后均为 `true`，保留独立加入权限。直接选课对应当前发布版本。
2. 分配课程/加入班级会创建 `direct_access=false` 的记录以兼容旧 submissions/feedback 外键；记录本身不授予学习权。
3. 班级授权要求当前成员关系 + 未撤销分配 + 对应版本。移除成员或撤销分配立即撤销这一来源的访问；其他班级或独立选课来源继续有效。
4. 学生另行从公开目录加入课程时将记录升级为 `direct_access=true`。这是明确的独立加入操作。
5. 不删除历史回答或教师反馈；管理员下架会阻止所有版本的学习和提交。

旧工作台中的 `enrollments` 只将学生实际可学的当前版本视为已加入；旧版本班级安排通过 My Classes 进入。My Learning 现有汇总仍按当前课程版本计算，这次未新增全班或历史版本成绩报表。

## 开发边界

- 教师页面和交互：`src/modules/teacher/classes/`。
- 学生页面和加入交互：`src/modules/student/classes/`。
- 跨角色基础展示：`src/modules/platform/classes/`，复用公共 UI 和主题，不互相引用教师/学生模块。
- 合同：`shared/contracts/features/classrooms.ts`，13 项已实现；两项邮件邀请仍预留。
- 仓储：`shared/database/classroom-repository.ts`，Neon provider：`shared/database/classrooms.ts`。
- 服务：`platform/server/classroom-service.ts`；服务器调用 `platformExtensions.classrooms`。
- 客户端动作：从 `@/modules/platform/actions` 导入相应 Server Actions。actor 始终取自服务器会话。
- 迁移：`database/migrations/202610270002_classrooms.sql`。由负责人运行 `bash scripts/local.sh db:migrate`；不可修改已应用迁移。

仓储每次重新检查数据库角色。教师仅能管理本人班级，学生仅能读取当前加入的班级，学生不能查看名单。班级成员与课程分配写入均有事务；授予学习权限和创建历史 enrollment 同时完成。提交通过课程/成员/分配共享行锁与下架、移除成员、撤销分配协调；服务前置检查不是唯一防线。

## 旧共享数据库兼容

共享 Neon 中已有本地源码未包含的 `202610190001_classrooms.sql` / `202610200001_classroom_course.sql` 迁移，使用 `classrooms.course_id` 一班一课。新迁移兼容已有班级/成员表，保留旧列并解除其非空要求，将有效的旧课程关系补成指定当前发布版本的分配。旧 migration 不改动；以后新安排以 course_assignments 为准，不继续依赖旧单课程列。现有 enrollment 的来源无法从旧结构区分，迁移保守地保留为独立选课，不凭推测撤销旧访问。

迁移脚本也已改用事务级 advisory lock：在整个业务迁移事务内固定 Neon pooler 后端，提交/回滚自动释放锁；30 秒锁等待超时。避免旧会话级锁在事务池里遗留，导致下次迁移一直等待。当前已将新迁移应用到配置的 Neon，并重复运行验证已应用迁移被跳过、未遗留 advisory lock。
