# Neon 上线前检查

代码已经提供 Neon 仓储和真实认证，以下事项仍需在实际环境完成。

1. 创建项目，填写唯一 `.env`，运行 db:check 与 db:migrate，在开发分支验收。
2. 使用真实账号验证注册、登录、退出、学生/教师权限和不同账号之间的数据隔离。
3. 公共注册默认为学生；仅可信负责人运行教师分配命令。管理员业务功能另行确认。
4. 配置并验证邮箱验证、密码重置与 SMTP，明确账号管理流程。当前代码不声称邮箱已被验证。
5. 正式 BETTER_AUTH_URL 使用 HTTPS，密钥只配置在服务端，保留来源与 CSRF 检查。按实际代理设置可信 IP 与限流策略。
6. 完成业务测试、异常提示、备份恢复、迁移发布与运行日志，日志不记录密钥、密码或不必要的学习内容。
7. 文件上传与 AI 生成成本限制、任务队列、已发布课程版本升级按功能扩展接入。
8. 部署到支持 Node.js 与 PostgreSQL 连接的平台。云端运行 APP_MODE=neon，不复制 .local 演示文件，也不使用任意身份切换。

当前已经在本地嵌入式 PostgreSQL 上验证不等于已经连接 Neon 云端。只有完成实际连接与验收后才能标记云端部署成功。
